# PRD: 홀덤 트레이너 Phase 2

## 한 줄 정의
**핵심 퀴즈 경험을 확 개선**하고(진입장벽 낮추기 + 용어 순화 + 퀴즈 다양성), 그 위에 **리텐션 루프**를 얹어서 매일 돌아오는 앱으로 만든다.

---

## Phase 2의 두 축

```
[축 1] 핵심 경험 개선  →  "이거 재밌다, 나도 할 수 있겠다"  (먼저)
[축 2] 리텐션 루프      →  "오늘도 열어야지"                  (그 다음)
```

아무리 스트릭/하트를 달아도, 퀴즈 자체가 어렵고 딱딱하면 소용없다.
**축 1을 먼저 완성하고, 축 2를 얹는다.**

# 축 1: 핵심 경험 개선

## 문제 진단

### 1. 초보자 진입장벽이 높다
- Unit 1부터 "AKs", "오프수트", "포켓 페어" 같은 용어가 쏟아짐
- 홀덤 룰 자체를 모르는 사람은 바로 이탈
- "나도 할 수 있겠다"는 첫 성공 경험이 부족

### 2. 전문 용어가 그대로 노출
- 오답 피드백: "AKs은(는) UTG의 RFI 레인지(10.1%)에 포함됩니다"
- "밸류 3bet", "폴드 에퀴티", "블로커" — 입문자에게 외계어
- 용어사전은 있지만, 퀴즈 풀면서 별도로 찾아보지 않음

### 3. 퀴즈가 단조롭다
- RFI는 매번 "레이즈 or 폴드" 2택
- Facing RFI는 "3bet / 콜 / 폴드" 3택
- 같은 형식 반복 → 지루함. "포커 퀴즈"보다 "플래시카드" 느낌

## 해결책

### 1. Unit 0: 튜토리얼 — "홀덤이 처음이라면" 🎓

**목표**: 홀덤을 전혀 모르는 사람도 자신감을 갖고 Unit 1로 넘어가게.

**설계 원칙:**
- 100% 맞출 수 있는 문제들 (자신감 부여)
- 카드 그림을 직접 보여주며 설명
- 전문 용어 없이 일상 언어로

#### 레슨 구성

**Lesson 0-1: 홀덤 한 판의 흐름** (4문제)
> 가이드: "홀덤은 간단해요. 카드 2장 받고, 공유 카드 5장이 깔리고, 가장 좋은 조합 5장이 이기는 게임이에요."

| # | 질문 | 선택지 | 정답 | 피드백 |
|---|------|--------|------|--------|
| 1 | 홀덤에서 나한테 나눠지는 카드는 몇 장? | 2장 / 3장 / 5장 | 2장 | "맞아요! 이 2장을 '핸드'라고 불러요. 이 2장이 내 무기예요." |
| 2 | 테이블 가운데 깔리는 공유 카드는 총 몇 장? | 3장 / 4장 / 5장 | 5장 | "5장이 차례로 깔려요. 처음 3장(플랍), 1장(턴), 1장(리버) 순서예요." |
| 3 | 최종 승부는 몇 장으로 만드나요? | 내 2장 / 5장 조합 / 7장 전부 | 5장 조합 | "내 2장 + 공유 5장 중에서 가장 좋은 5장 조합이 내 패예요." |
| 4 | 상대보다 좋은 패를 가지면? | 이긴다 / 비긴다 / 다시 한다 | 이긴다 | "테이블에 쌓인 칩(돈)을 전부 가져가요! 이게 홀덤이에요." |

**Lesson 0-2: 패의 서열** (5문제)
> 가이드: "어떤 패가 강한지 알아야 게임을 할 수 있어요. 원페어 < 투페어 < 트리플 < 스트레이트 < 플러시 순서예요."

| # | 질문 | 선택지 | 정답 | 피드백 |
|---|------|--------|------|--------|
| 1 | 같은 숫자 2장이 있으면? | 원페어 / 투페어 | 원페어 | "원페어예요! 예: K♠ K♥" |
| 2 | 원페어와 투페어 중 뭐가 더 강하나요? | 원페어 / 투페어 | 투페어 | "투페어가 더 강해요. 만들기가 더 어려우니까요." |
| 3 | 숫자가 연속 5개면? (예: 5-6-7-8-9) | 스트레이트 / 플러시 | 스트레이트 | "스트레이트! 숫자 5개가 계단처럼 이어지는 거예요." |
| 4 | 같은 무늬 5장이면? | 스트레이트 / 플러시 | 플러시 | "플러시! 하트 5장, 스페이드 5장처럼 무늬가 같으면 돼요." |
| 5 | 스트레이트와 플러시 중 뭐가 더 강하나요? | 스트레이트 / 플러시 | 플러시 | "플러시가 더 강해요. 같은 무늬 5장이 더 만들기 어렵거든요." |

**Lesson 0-3: 베팅의 기본** (4문제)
> 가이드: "매 라운드마다 선택이 있어요. 패가 좋으면 돈을 더 넣고(베팅/레이즈), 애매하면 지켜보고(체크/콜), 안 되겠으면 포기해요(폴드)."

| # | 질문 | 선택지 | 정답 | 피드백 |
|---|------|--------|------|--------|
| 1 | 내 패가 AA(에이스 한 쌍)일 때, 가장 좋은 선택은? | 돈을 더 넣기 / 포기하기 | 돈을 더 넣기 | "AA는 최강 패! 당연히 돈을 더 넣어야죠. 이걸 '레이즈'라고 해요." |
| 2 | 내 패가 7♠ 2♦일 때, 보통 어떻게 하나요? | 돈을 더 넣기 / 포기하기 | 포기하기 | "72는 가장 약한 패예요. 이럴 때 포기하는 걸 '폴드'라고 해요." |
| 3 | 상대가 베팅했는데 내 패가 괜찮을 때? | 같은 금액 내기 / 포기하기 | 같은 금액 내기 | "같은 금액을 내는 걸 '콜'이라고 해요. 게임을 계속할 수 있어요." |
| 4 | 누구도 베팅 안 했을 때 나도 안 내고 넘기는 건? | 체크 / 콜 | 체크 | "아무도 안 걸었으면 나도 그냥 넘길 수 있어요. 이게 '체크'예요." |

### 2. 용어 순화 — 피드백 전면 리라이팅 📝

**원칙:**
- 전문 용어 대신 **일상 언어** 사용
- 꼭 필요한 용어는 **괄호 안에 용어명 병기** (자연스럽게 학습)
- 짧고 따뜻한 톤 (선생님이 아니라 친구가 알려주는 느낌)

#### Before → After 예시

**RFI — 레이즈가 정답인데 폴드한 경우:**
```
[Before]
"AKs은(는) UTG의 RFI 레인지(10.1%)에 포함됩니다. 레이즈!"

[After]
"AKs는 아주 강한 패예요! 💪
이 자리(UTG)에서는 상위 10%의 좋은 패만 베팅하는데,
에이스-킹 같은 무늬는 당연히 포함돼요. 자신있게 레이즈!"
```

**RFI — 폴드가 정답인데 레이즈한 경우:**
```
[Before]
"KJo은(는) UTG RFI 레인지에 포함되지 않습니다.
오프수트 브로드웨이이지만 UTG에서는 너무 약합니다."

[After]
"KJ 다른 무늬는 나쁘지 않은 패지만,
이 자리(UTG)는 뒤에 8명이나 남아있어서
정말 좋은 패만 골라야 해요.
KQ까지만 OK, KJ는 참고 접는 게 이득이에요."
```

**Facing RFI — 3bet이 정답:**
```
[Before]
"AKs은(는) CO에서 UTG 오픈에 밸류 3bet 합니다.
강한 핸드로 팟을 키워요!"

[After]
"AK 같은 무늬는 여기서 다시 올려야 해요! (이걸 '3벳'이라고 해요)
상대가 먼저 베팅했지만, 내 패가 더 강을 확률이 높으니까
돈을 더 넣어서 판을 키우는 거예요."
```

**Facing RFI — 폴드가 정답:**
```
[Before]
"T7o은(는) BTN에서 UTG 오픈에 폴드합니다.
오프너의 레인지를 상대하기엔 너무 약합니다."

[After]
"T7 다른 무늬로는 여기서 싸우기 어려워요.
상대가 앞자리(UTG)에서 베팅했다는 건
정말 좋은 패를 들고 있다는 뜻이거든요.
이런 상대한테 약한 패로 덤비면 손해예요. 접는 게 현명해요."
```

**vs 3bet — 콜이 정답:**
```
[Before]
"QQ는 CO에서 BTN 3bet에 콜합니다.
4bet하기엔 상대 레인지가 좁고, 폴드하기엔 너무 강합니다."

[After]
"QQ는 아주 좋은 패지만, 상대가 다시 올렸으니(3벳) 잠깐 신중해야 해요.
한 번 더 올리기엔(4벳) 좀 부담스럽고,
접기엔 너무 아까운 패예요.
여기선 따라가면서(콜) 다음 카드를 보는 게 최선!"
```

### 3. 퀴즈 다양성 — "포커 퀴즈" 느낌 강화 🎲

**목표**: 단순 2~3택 반복에서 벗어나, 다양한 형태의 질문으로 재미를 높인다.

#### 새로운 퀴즈 유형

**A. 상황 판단형** — "왜 그렇게 하는지" 이해도를 묻는다
```
[상황] UTG에서 A5s를 받았어요.
[질문] 이 패로 베팅하는 이유는?

○ 에이스가 있으니까 무조건 강하다
○ 같은 무늬라서 플러시 가능성 + 에이스 블로커 (정답)
○ 작은 숫자지만 페어가 되면 강하다
○ 상대를 겁주려고
```

**B. 비교 선택형** — 두 핸드 중 어떤 게 더 나은지
```
[상황] CO에서 한 핸드만 베팅할 수 있다면?

○ KJo (킹-잭 다른 무늬)
○ 87s (8-7 같은 무늬) (정답)

피드백: "87 같은 무늬는 스트레이트 + 플러시 두 가지 가능성이 있어요.
KJ 다른 무늬보다 '될 수 있는 패'가 더 많답니다!"
```

**C. 포지션 감각형** — 같은 패, 다른 자리
```
[질문] KTs(킹-텐 같은 무늬)로 베팅해도 되는 자리는?
       (여러 개 선택 가능)

□ UTG (앞자리) — 아슬아슬, 보통 접어요
☑ HJ (중간)    — OK!
☑ CO (뒷자리)  — OK!
☑ BTN (버튼)   — 당연히 OK!
```

**D. OX 퀵 퀴즈** — 빠른 직관 테스트
```
"BTN에서는 절반 이상의 패로 베팅할 수 있다"  → O (51%)
"UTG에서 AJo로 베팅해도 된다"              → X (UTG 레인지 밖)
"같은 무늬(수티드)가 다른 무늬보다 항상 강하다" → O
```

#### 기존 레슨에 새 퀴즈 유형 배치

| 유닛 | 추가할 퀴즈 유형 | 효과 |
|------|-----------------|------|
| Unit 1-2 (기초) | OX 퀵 퀴즈 + 비교 선택 | 부담 없이 개념 확인 |
| Unit 3-4 (RFI) | 상황 판단형 + 포지션 감각형 | "왜?"를 이해하게 |
| Unit 5-6 (대응) | 상황 판단형 | 단순 암기 → 이해로 전환 |

#### 기존 퀴즈와의 공존
- 기존 "레이즈/폴드" 퀴즈는 **그대로 유지** (핵심 드릴)
- 새 퀴즈 유형은 레슨 앞쪽 30%(워밍업)에 배치
- 레슨당 새 유형 1~2문제 + 기존 드릴 4~6문제 = 총 6~8문제

## Unit 0의 스킬 트리 통합

```
[Unit 0: 홀덤 첫걸음]  ← 새로 추가 (튜토리얼, 잠금 없음)
  ├─ 0-1. 홀덤 한 판의 흐름
  ├─ 0-2. 패의 서열
  └─ 0-3. 베팅의 기본
       ↓
[Unit 1: 핸드의 세계]  ← 기존 (Unit 0 완료 후 잠금해제)
  ├─ 1-1. 카드 읽기
  ...
```

- Unit 0는 **처음 접속 시 자동으로 열려있음**
- Unit 0 완료가 Unit 1 잠금해제 조건
- 이미 Unit 1+를 진행한 기존 유저는 Unit 0 자동 완료 처리

# 축 2: 리텐션 루프

> 축 1(핵심 경험 개선)이 완료된 후 진행한다.

## P0: 반드시 구현

### 1. 스트릭 (연속 학습일)

| 항목 | 설계 |
|------|------|
| 스트릭 조건 | 하루에 레슨 1개 이상 완료 (자유연습 X) |
| 기준 시간 | 자정(KST) 리셋 |
| 표시 위치 | 메인 화면 상단 (XP바 옆) |
| 보상 | 7일: +50 XP, 30일: +200 XP, 100일: +500 XP |

**UX 흐름:**
```
[메인 화면]  3일 연속!
[레슨 완료]  오늘도 완료! 스트릭 유지!
[건너뛴 후]  스트릭이 리셋되었습니다. 다시 시작해보세요!
```

### 2. 전역 하트 시스템

| 항목 | 설계 |
|------|------|
| 최대 하트 | 5개 |
| 소모 | 레슨 중 오답 1개 = 하트 -1 |
| 회복 | 30분마다 1개 자동 회복 (최대 5개) |
| 하트 0 | 레슨 시작 불가. "OO분 후 회복" 표시 |
| 자유연습 | 하트 소모 없음 |

> 원래 PRD는 4시간마다 회복이었는데, 30분으로 조정. 유저가 적은 초기에 너무 오래 기다리면 이탈. 나중에 조절.

## 기술 설계

### DB 변경

```sql
-- 스트릭 추적 (신규)
CREATE TABLE user_streaks (
  user_id UUID PRIMARY KEY REFERENCES auth.users(id),
  current_streak INT DEFAULT 0,
  longest_streak INT DEFAULT 0,
  last_active_date DATE,
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 전역 하트 (신규)
CREATE TABLE user_hearts (
  user_id UUID PRIMARY KEY REFERENCES auth.users(id),
  hearts INT DEFAULT 5 CHECK (hearts >= 0 AND hearts <= 5),
  last_recovery_at TIMESTAMPTZ DEFAULT now()
);
```
